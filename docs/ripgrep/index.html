ripgrep — codebase report

Built 2026-11-11 at commit 178cc02

ripgrep (rg) is a line-oriented recursive search tool written in Rust: it walks a directory tree, skips what .gitignore, hidden-file and file-type rules exclude, and prints lines that match a regex. The repo is a Cargo workspace of one binary (crates/core, built as rg) and a set of library crates that the binary uses through the grep facade crate (search) and the ignore crate (directory walk); the measured tree holds 223 files and 75535 lines, of which 55512 are Rust. Start at crates/core/main.rs (main, run, search_parallel), then follow one file through the searcher and printer crates, and read the ignore crate when you need to know why a path was or was not searched. History is available (2240 commits since 2016). No ER diagram, sitemap, state, journey or swimlane chart: there is no database, no site, no status lifecycle and no multi-role process in the code. All four core charts are drawn.

The stack

The binary crate (rg) depends on two things: the grep facade, which re-exports the cli, matcher, regex, searcher and printer crates (and pcre2 when the feature is on), and the ignore crate, which does the directory walk. Every engine and printer is written against the Matcher trait in grep-matcher, so the Rust regex engine and PCRE2 are interchangeable. Read this first: it tells you which crate to open for which question. Third-party crates are left out to keep the picture readable.

Startup: argv to a run mode

main calls flags::parse, which parses argv into a low-level LowArgs struct, optionally prepends arguments from the file named by RIPGREP_CONFIG_PATH and parses again, then converts the result into HiArgs. Help and version requests short-circuit before the config is read. run then matches on the mode: search (single or multi-threaded), file listing, type listing or generating completions and man pages. Everything later in the report starts from a HiArgs.

One file through the search pipeline

search_parallel asks HiArgs for a matcher, a searcher and a printer, wraps them in a SearchWorker, and runs the directory walk with one closure per thread. For each file the worker picks a path (stdin, preprocessor, decompression or plain), and the searcher, here the memory-mapped slice path (taken only for at most 10 paths that are all files; a directory search reads line by line), scans line by line, asks the matcher for a candidate line and hands each match to the printer's sink. The sink writes into a per-file buffer that main prints in one locked write, which keeps output from different threads from interleaving.

The parallel directory walk

WalkParallel gives each thread a work-stealing deque (crossbeam_deque) seeded with the root paths. A worker pops or steals an entry; for a directory it reads it, visits it, asks the Ignore matcher about each child and pushes the kept children back as new work. The caller's closure is run for every entry the walk visits. When a worker has nothing to pop or steal it marks itself idle and polls; when every worker is idle, the walk ends.

How a path is ignored

Ignore::matched answers in a fixed order: explicit overrides (the --glob flag) win, then the ignore files (.ignore, .gitignore, git exclude), then file-type filters; only if nothing matched does matched_dir_entry apply the hidden-file check. A whitelist match from an ignore file or a type is remembered and returned if nothing later ignores the path. The same function serves the single-threaded Walk and the parallel Worker, so both walks skip the same paths.

How the searcher reads a file

Searcher::search_path ends in one of three line-search strategies. If a memory map is allowed and opens, it searches the mapped slice (SliceByLine); ripgrep only allows maps when at most 10 explicit paths are given and all are files. Otherwise it reads the whole file onto the heap for multi-line search (MultiLine), or streams it through a decoder and a rolling line buffer (ReadByLine). Knowing which of these runs explains most performance differences between invocations.

Which regex engine builds the matcher

HiArgs::matcher looks at the engine flag. The default builds the Rust regex matcher and, on failure, returns an error that suggests PCRE2; the pcre2 choice builds only PCRE2; auto tries Rust first and falls back to PCRE2, printing both errors if both fail. PCRE2 exists only when ripgrep is built with the pcre2 feature.
